# UI capture fixtures

The screenshots render the actual page components with fixed API data, inert server actions and router boundaries. They use the gateway's self-hosted Geist fonts and theme. They omit the application shell and do not represent a live authenticated staging walk. The standalone toast cases exercise the notification hosts with fixture copy.

The baseline is `33d8b7ccd63cef29de841f862af2dc1bfdafbf30`, with its own locked dependencies. Each fixture has a before and after image at 375, 1440 and 1920 in light and dark. The capture fails on browser exceptions or document overflow. The Parties table keeps its own horizontal scrolling.

## Reproduce

From the repository root, create a baseline checkout and an isolated Playwright installation:

```sh
git worktree add --detach /tmp/gateway-ui-before 33d8b7ccd63cef29de841f862af2dc1bfdafbf30
npm ci --prefix /tmp/gateway-ui-before --ignore-scripts --no-audit --no-fund
npm install --prefix /tmp/gateway-ui-tools --no-save playwright@1.65.1
UI_CAPTURE_TOOLS=/tmp/gateway-ui-tools UI_CAPTURE_BEFORE=/tmp/gateway-ui-before node test/evidence/ui-package/capture.mjs
```

The final JSON reports the number of screenshots and any failures. Set `UI_CAPTURE_VERSION=after` and `UI_CAPTURE_SCENARIO` to one fixture below to narrow the run. With `UI_INTERACTION_CHECK=1`, the `a2a-agent` fixture verifies the selected plugin scope's form value, and `outside-party-agent` verifies that Repeatable submits its action. Interaction checks leave the screenshot files intact.
